Bugs Críticos — Podem Causar Falhas em Produção

Problemas que devem ser corrigidos antes de qualquer nova funcionalidade

Geolocalização Síncrona no Middleware Crítico

Cada request autenticado faz uma chamada HTTP externa ao ip-api.com com timeout de 3 segundos. Se o serviço estiver lento, todos os utilizadores ficam bloqueados 3 segundos por request. Em produção com 20 utilizadores simultâneos, isto pode derrubar o servidor.

📄 app/Http/Middleware/LogSessionActivity.php:64
✦ Solução
// Mover para Job assíncrono GeolocateSessionJob::dispatch($sessionId, $ip) ->onQueue('low');
Assinaturas Base64 na Base de Dados Crítico

Os campos firma e firma_devolucion são longText. Uma assinatura base64 ocupa ~50-80KB. Com 1000 entregas, são ~80MB só nestes campos. A SignatureService::store() existe mas não está a ser usada consistentemente.

📄 app/Models/EpiEntrega.php 📄 app/Models/FerramentaLog.php
✦ Solução
// Sempre usar SignatureService::store() // antes de persistir qualquer assinatura $path = SignatureService::store($base64Data); $entrega->firma = $path;
Stock EPI Pode Ficar Negativo Aviso

O applyDelta() não valida se o resultado será negativo antes de persistir. A validateStock() existe mas só é chamada no formulário — não nos observers. Uma entrega criada via API ou Tinker pode quebrar o inventário.

📄 app/Services/EpiStockService.php
✦ Solução
// Adicionar no applyDelta() antes de save if ($item->stock_total + $delta < 0) { throw new StockInsuficienteException(); }
PIN do Colaborador em Texto Plano Segurança

O PIN de 4 dígitos dos colaboradores está armazenado sem hash na base de dados. Se a DB vazar, todos os PINs ficam imediatamente expostos. Deve usar Hash::make() tal como a password do User.

📄 app/Models/Colaborador.php
✦ Solução
// Cast no modelo protected $casts = ['pin' => 'hashed']; // Verificação no login Hash::check($inputPin, $colaborador->pin);
Timezone UTC para Aplicação Portuguesa Aviso

O config/app.php define timezone = UTC. Todas as datas guardadas e exibidas estão desfasadas 1h (inverno) ou 2h (verão) em relação ao horário de Lisboa — afeta logs, timestamps de atribuições, datas de entregas e relatórios.

📄 config/app.php
✦ Solução (5 minutos)
'timezone' => 'Europe/Lisbon',
Sem Policies de Recurso (Authorization) Arquitetura

O middleware verifica se o utilizador tem o role epi, mas não verifica permissões sobre recursos específicos. Qualquer utilizador epi pode editar qualquer item do catálogo EPI. À medida que o sistema crescer, isto tornará o controlo de acesso impossível de auditar.

📄 app/Http/Middleware/EnsureIsEpi.php
✦ Solução
// php artisan make:policy EpiItemPolicy // Implementar can('update', $epiItem) // nos componentes Livewire

Escalabilidade e Manutenibilidade

Riscos a médio/longo prazo à medida que o volume de dados e utilizadores cresce

Enums para Estados de Processo Manutenção

Os estados 'pendente', 'aprovado', 'entregue', 'rejeitado' estão espalhados em vistas, componentes e queries. Se um estado mudar, há múltiplos pontos de falha silenciosa.

✦ Solução com PHP 8.1 Enums
enum EpiPedidoEstado: string { case Pendente = 'pendente'; case Aprovado = 'aprovado'; case Entregue = 'entregue'; case Rejeitado = 'rejeitado'; }
Queue Worker para Operações Lentas Performance

Não há Jobs assíncronos implementados. Quando o volume crescer — exportações Excel grandes, envio de notificações, processamento de imagens — tudo vai bloquear o request HTTP. As tabelas de jobs já existem na DB, só falta usar.

✦ Candidatos a Jobs
GeolocateSessionJob SendPushNotificationJob ExportEpiHistoricoJob ProcessSignatureImageJob
Archival Strategy para Logs DB Growth

As tabelas user_sessions, ferramenta_logs e vehicle_driver_logs crescem indefinidamente. Sem uma estratégia de arquivo (ex: purgar registos com mais de 2 anos), a DB vai degradar ao longo do tempo.

✦ Solução
// Scheduled command (routes/console.php) Schedule::command('app:purge-old-sessions') ->monthly();
Testes de Componentes Livewire Qualidade

O path crítico dos trabalhadores mobile (PhoneDisplay — login, aceitar termos, solicitar EPI, reportar incidente) não tem nenhum teste automatizado. Uma regressão neste fluxo pode passar despercebida indefinidamente.

✦ Exemplo com Pest + Livewire
it('allows worker to request EPI', function () { $colaborador = Colaborador::factory()->create(); Livewire::test(PhoneDisplay::class) ->call('autenticar', $colaborador->pin) ->assertSet('activeColaboradorId', $colaborador->id); });

Roadmap de Funcionalidades

Módulos relevantes para um gestor de estaleiro naval, ordenados por impacto operacional

⏱

Controlo de Ponto Digital

● Prioridade Alta

O sistema já regista quem está em que PEP cada dia (Atribuicao), mas não regista horas de entrada/saída. A adição natural seria check-in/check-out no PhoneDisplay via PIN ou QR code do colaborador.

  • Check-in / check-out no ecrã mobile
  • Relatório mensal de horas por colaborador
  • Alertas de ausências não justificadas
  • Exportação para folha de salários (CSV/Excel)
📱

Push Notifications Reais (PWA)

● Prioridade Alta

O sistema tem AppNotification e o PhoneDisplay funciona como PWA, mas as notificações são apenas in-app (polling a cada 20s). Com Web Push API, os trabalhadores receberiam alertas mesmo com o telemóvel fechado.

  • Service Worker + Web Push API
  • Alertas de EPI aprovado / documento a vencer
  • Urgências de segurança em tempo real
  • Assinaturas pendentes
⚠️

Não-Conformidades e Ações Corretivas

● Prioridade Alta

Os IncidentReport existem mas são básicos. Um módulo CAPA completo (Corrective and Preventive Action) é obrigatório para certificações ISO 45001 em ambiente de estaleiro.

  • Criação mobile-first com foto e geolocalização
  • Atribuição de responsável + prazo de resolução
  • Workflow de aprovação e fecho
  • Dashboard de KPIs de segurança (taxa acidentes/mês)
  • Histórico auditável por não-conformidade
📜

Validade de Certificações por Colaborador

● Prioridade Média

Cada trabalhador de estaleiro tem certificados com prazo: trabalho em altura, soldadura, manobrador de grua, espaços confinados. O sistema deve alertar e bloquear atribuições quando um certificado está vencido.

  • Upload de documentos por colaborador
  • Alertas automáticos 30/15/7 dias antes do vencimento
  • Bloqueio de atribuição a PEPs que requeiram a certificação
  • Relatório de conformidade da equipa
✅

Checklists Digitais de Inspeção

● Prioridade Média

Além das ferramentas (FerramentaLog), um módulo genérico de checklists digitais para inspeções recorrentes com assinatura e foto integradas.

  • Inspeção diária de veículos (pre-trip check)
  • Verificação de andaimes e EPC
  • Checklists customizáveis por tipo de ativo
  • Histórico com assinatura digital e timestamp
  • Alertas de checklists em atraso
🏢

Gestão de Subempreiteiros

● Prioridade Média

Em estaleiros, uma parte significativa da força de trabalho é subcontratada. O sistema atual só gere colaboradores internos, criando um ponto cego operacional.

  • Registo de empresas subcontratadas
  • Colaboradores subcontratados com validade de contrato
  • Atribuição aos mesmos PEPs que internos
  • Controlo de documentação (seguros, certidões fiscais)
  • Separação de EPIs internos vs. subempreiteiros
📊

Planeamento Visual de Recursos

● Prioridade Média

O PepBoard existe mas é provavelmente uma visão de dia. Um Gantt por semana/mês com drag-and-drop seria muito valioso para chefes de equipa planearem alocações com antecedência.

  • Vista semanal e mensal de alocações
  • Drag-and-drop para reagendamento
  • Detecção de conflitos (mesmo colaborador em 2 PEPs)
  • Exportação para PDF para reuniões de planeamento
🔗

API REST para Integração ERP

● Prioridade Baixa

Se a empresa usa SAP, Primavera, PHC ou similar, uma API de sincronização bidirecional elimina a duplicação de dados entre sistemas. O Laravel 12 tem suporte nativo a API Resources.

  • API de colaboradores (sincronizar com RH)
  • API de EPIs (sincronizar com contabilidade/compras)
  • Webhooks para eventos críticos
  • Autenticação via API tokens (Sanctum)
📉

Business Intelligence Self-Hosted

● Prioridade Baixa

Os módulos ResumoMensal e Estatisticas existem mas são básicos. Metabase (open-source, gratuito) conectado diretamente à mesma DB daria dashboards avançados sem desenvolvimento adicional.

  • Dashboards interativos para gestão
  • KPIs de segurança (TIFR, TISR, etc.)
  • Análise de consumo de EPIs por departamento
  • Relatórios automáticos por email
